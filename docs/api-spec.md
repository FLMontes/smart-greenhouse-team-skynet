# API REST - Smart Greenhouse

Este documento define el contrato de API REST utilizado para la comunicación entre la ESP32, el backend y el frontend del sistema Invernadero Inteligente.

La ESP32 envía mediciones al backend mediante HTTP REST.  
El frontend consulta al backend para visualizar mediciones, alertas, estado de actuadores y resultados de algoritmos.

## OpenAPI

```yaml
openapi: 3.0.0 
 
info: 
  title: Smart Greenhouse API 
  version: 1.2.0 
  description: API for greenhouse monitoring, historical storage, actuator commands, alerts, and algorithm visualization. 
 
paths: 
  /api/measurements: 
    post: 
      summary: Create a new measurement 
      description: Receives sensor measurements from the ESP32, validates them and stores them in PostgreSQL. 
      operationId: createMeasurement 
      requestBody: 
        required: true 
        content: 
          application/json: 
            schema: 
              $ref: '#/components/schemas/MeasurementInput' 
      responses: 
        '201': 
          description: Measurement stored successfully. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/Measurement' 
        '400': 
          description: Invalid request payload. The backend must not persist invalid measurements. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
    get: 
      summary: Get historical measurements 
      description: Returns historical measurements stored in PostgreSQL. 
      operationId: getMeasurements 
      parameters: 
        - name: limit 
          in: query 
          required: false 
          description: Maximum number of measurements to return. 
          schema: 
            type: integer 
            default: 100 
            minimum: 1 
            maximum: 1000 
        - name: offset 
          in: query 
          required: false 
          description: Number of measurements to skip before starting to return results. 
          schema: 
            type: integer 
            default: 0 
            minimum: 0 
      responses: 
        '200': 
          description: Historical measurements. 
          content: 
            application/json: 
              schema: 
                type: array 
                items: 
                  $ref: '#/components/schemas/Measurement' 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
  /api/measurements/latest: 
    get: 
      summary: Get latest measurement 
      description: Returns the most recent measurement stored by the backend. This endpoint can be used by the frontend for live visualization through polling. 
      operationId: getLatestMeasurement 
      responses: 
        '200': 
          description: Latest measurement data. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/Measurement' 
        '404': 
          description: No measurements found. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
  /api/actuators/status: 
    get: 
      summary: Get current actuator status 
      description: Returns the latest actuator commands generated by backend alert and control algorithms for the ESP32. 
      operationId: getActuatorStatus 
      responses: 
        '200': 
          description: Current logical commands for actuators. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ActuatorStatus' 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
  /api/alerts: 
    get: 
      summary: Get active alerts 
      description: Returns active alerts generated by backend algorithms. 
      operationId: getAlerts 
      responses: 
        '200': 
          description: List of active alerts. 
          content: 
            application/json: 
              schema: 
                type: array 
                items: 
                  $ref: '#/components/schemas/Alert' 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
  /api/algorithms: 
    get: 
      summary: Get available algorithms 
      description: Returns the configured backend algorithms. At least three of them must be implemented and linked to measurements stored in PostgreSQL. 
      operationId: getAlgorithms 
      responses: 
        '200': 
          description: Available backend algorithms. 
          content: 
            application/json: 
              schema: 
                type: array 
                minItems: 3 
                items: 
                  $ref: '#/components/schemas/AlgorithmDefinition' 
              example: 
                - name: MovingAverageStrategy 
                  description: Calculates the moving average of measurements using a sliding window. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Recent measurement values from stored records. 
                  outputName: averageValue 
                  outputUnit: "various" 
                - name: TemperatureStrategy 
                  description: Evaluates temperature boundaries (min/max) and generates cold/heat alerts and actuator commands. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Latest stored temperature value. 
                  outputName: temperatureStatus 
                  outputUnit: "status" 
                - name: CO2Strategy 
                  description: Evaluates CO2 concentration against the maximum threshold to determine ventilation needs. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Latest stored CO2 value. 
                  outputName: ventilationRequired 
                  outputUnit: "boolean" 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
  /api/algorithms/latest: 
    get: 
      summary: Get latest algorithm results 
      description: Returns the latest results generated by backend processing algorithms using measurements stored in PostgreSQL. This endpoint can be used by the frontend for live visualization through polling. 
      operationId: getLatestAlgorithmResults 
      responses: 
        '200': 
          description: Latest algorithm outputs. 
          content: 
            application/json: 
              schema: 
                type: array 
                items: 
                  $ref: '#/components/schemas/AlgorithmResult' 
              example: 
                - algorithm: MovingAverageStrategy 
                  description: Calculates the moving average of temperature using a sliding window. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Last 10 stored measurements. 
                  outputName: averageTemperature 
                  value: 25.7 
                  unit: "°C" 
                  timestamp: "2026-06-01T20:30:00Z" 
                - algorithm: TemperatureStrategy 
                  description: Evaluates temperature boundaries to trigger actuator decisions. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Latest stored measurement. 
                  outputName: isTooCold 
                  value: 0 
                  unit: "boolean" 
                  timestamp: "2026-06-01T20:30:00Z" 
                - algorithm: CO2Strategy 
                  description: Evaluates CO2 concentration to determine ventilation needs. 
                  inputSource: PostgreSQL measurements table 
                  inputData: Latest stored measurement. 
                  outputName: ventilationRequired 
                  value: 1 
                  unit: "boolean" 
                  timestamp: "2026-06-01T20:30:00Z" 
        '500': 
          description: Internal server error. 
          content: 
            application/json: 
              schema: 
                $ref: '#/components/schemas/ErrorResponse' 
 
components: 
  schemas: 
    MeasurementInput: 
      type: object 
      required: 
        - temperature 
        - humidity 
        - light 
        - co2 
        - buttonPressed 
      properties: 
        temperature: 
          type: number 
          format: float 
          minimum: -10 
          maximum: 60 
          example: 24.5 
          description: Air temperature in Celsius. 
 
        humidity: 
          type: number 
          format: float 
          minimum: 0 
          maximum: 100 
          example: 60.2 
          description: Air humidity percentage. 
 
        light: 
          type: number 
          format: float 
          minimum: 0 
          maximum: 100000 
          example: 800.0 
          description: Light intensity level in lux. 
 
        co2: 
          type: number 
          format: float 
          minimum: 0 
          maximum: 5000 
          example: 450.0 
          description: CO2 concentration in ppm. 
 
        buttonPressed: 
          type: boolean 
          example: false 
          description: Indicates whether the physical button connected to the ESP32 was pressed. 
 
    Measurement: 
      allOf: 
        - $ref: '#/components/schemas/MeasurementInput' 
        - type: object 
          required: 
            - id 
            - timestamp 
          properties: 
            id: 
              type: integer 
              format: int64 
              example: 152 
              description: Unique identifier of the stored measurement. 
 
            timestamp: 
              type: string 
              format: date-time 
              example: "2026-06-01T20:30:00Z" 
              description: Timestamp generated by the backend when the measurement was stored. 
 
    Alert: 
      type: object 
      required: 
        - id 
        - type 
        - message 
        - severity 
        - active 
        - relatedMeasurementId 
        - timestamp 
      properties: 
        id: 
          type: integer 
          format: int64 
          example: 34 
          description: Unique identifier of the alert. 
 
        type: 
          type: string 
          example: HIGH_TEMPERATURE 
          description: Logical alert type generated by the backend. 
 
        message: 
          type: string 
          example: Temperature exceeded threshold. 
          description: Human-readable alert message. 
 
        severity: 
          type: string 
          enum: 
            - LOW 
            - MEDIUM 
            - HIGH 
          example: HIGH 
          description: Alert severity level. 
 
        active: 
          type: boolean 
          example: true 
          description: Indicates whether the alert is currently active. 
 
        relatedMeasurementId: 
          type: integer 
          format: int64 
          example: 152 
          description: Identifier of the measurement that caused or is related to the alert. 
 
        timestamp: 
          type: string 
          format: date-time 
          example: "2026-06-01T20:30:00Z" 
          description: Timestamp when the alert was generated. 
 
    ActuatorStatus: 
      type: object 
      required: 
        - fanStatus 
        - buzzerStatus 
        - motorStatus 
        - resistorStatus 
        - rgbColorCommand 
        - ledIntensityCommand 
        - basedOnMeasurementId 
        - timestamp 
      properties: 
        fanStatus: 
          type: boolean 
          example: true 
          description: Logical command to activate or deactivate the fan. 
 
        buzzerStatus: 
          type: boolean 
          example: false 
          description: Logical command to trigger or mute the alarm buzzer. 
 
        motorStatus: 
          type: boolean 
          example: false 
          description: Logical command to activate or deactivate the watering motor. 
 
        resistorStatus: 
          type: boolean 
          example: false 
          description: Logical command to activate or deactivate the heating resistor. 
 
        rgbColorCommand: 
          type: string 
          pattern: '^#[0-9A-Fa-f]{6}$' 
          example: "#FF0000" 
          description: Hex color code for the status RGB LED strip. 
 
        ledIntensityCommand: 
          type: integer 
          minimum: 0 
          maximum: 100 
          example: 80 
          description: Intensity percentage level for the lighting LED strip. 
 
        basedOnMeasurementId: 
          type: integer 
          format: int64 
          example: 152 
          description: Measurement used to generate these actuator commands. 
 
        timestamp: 
          type: string 
          format: date-time 
          example: "2026-06-01T20:30:00Z" 
          description: Timestamp when the actuator commands were generated. 
 
    AlgorithmDefinition: 
      type: object 
      required: 
        - name 
        - description 
        - inputSource 
        - inputData 
        - outputName 
        - outputUnit 
      properties: 
        name: 
          type: string 
          enum: 
            - TemperatureStrategy 
            - HumidityStrategy 
            - CO2Strategy 
            - LightStrategy 
            - MovingAverageStrategy 
          example: MovingAverageStrategy 
          description: Name of the backend algorithm. 
 
        description: 
          type: string 
          example: Calculates the moving average using recent stored measurements. 
          description: Purpose of the algorithm. 
 
        inputSource: 
          type: string 
          example: PostgreSQL measurements table 
          description: Data source used by the algorithm. 
 
        inputData: 
          type: string 
          example: Recent measurement values from stored records. 
          description: Input data required by the algorithm. 
 
        outputName: 
          type: string 
          example: averageValue 
          description: Name of the output generated by the algorithm. 
 
        outputUnit: 
          type: string 
          example: "°C" 
          description: Unit of measurement associated with the algorithm output. 
 
    AlgorithmResult: 
      type: object 
      required: 
        - algorithm 
        - description 
        - inputSource 
        - inputData 
        - outputName 
        - value 
        - unit 
        - timestamp 
      properties: 
        algorithm: 
          type: string 
          enum: 
            - TemperatureStrategy 
            - HumidityStrategy 
            - CO2Strategy 
            - LightStrategy 
            - MovingAverageStrategy 
          example: MovingAverageStrategy 
          description: Name of the algorithm that generated the result. 
 
        description: 
          type: string 
          example: Calculates the moving average using recent stored measurements. 
          description: Purpose of the algorithm result. 
 
        inputSource: 
          type: string 
          example: PostgreSQL measurements table 
          description: Data source used by the algorithm. 
 
        inputData: 
          type: string 
          example: Last 10 stored measurements. 
          description: Input data used by the algorithm. 
 
        outputName: 
          type: string 
          example: averageValue 
          description: Name of the output generated by the algorithm. 
 
        value: 
          type: number 
          format: float 
          example: 25.7 
          description: Numeric value generated by the algorithm. 
 
        unit: 
          type: string 
          example: "°C" 
          description: Unit of measurement associated with the algorithm result. 
 
        timestamp: 
          type: string 
          format: date-time 
          example: "2026-06-01T20:30:00Z" 
          description: Timestamp when the algorithm result was generated. 
 
    ErrorResponse: 
      type: object 
      required: 
        - error 
        - message 
        - timestamp 
      properties: 
        error: 
          type: string 
          example: INVALID_REQUEST 
          description: Machine-readable error code. 
 
        message: 
          type: string 
          example: Invalid request payload. 
          description: Human-readable error message. 
 
        timestamp: 
          type: string 
          format: date-time 
          example: "2026-06-01T20:30:00Z" 
          description: Timestamp when the error occurred. 
 
 
```
